# ASM Alpha 8 Coding DEV8.1 — Research-loop hardening (implementation report)

Status: **experimental; NOT promoted**. Built on `asm_alpha8_dev9` (DEV9 code carried along unchanged). All earlier releases preserved.
New: `asm/coding/sandbox.py`. Rewritten: `asm/coding/research.py`. DEV7's `TestRunner` is untouched (legacy runners are auto-wrapped).

## What changed, by requested item
1. **Strict time budgets incl. generator timeouts.** One wall-clock deadline covers baseline, generator calls and every test run; each step gets `min(own timeout, remaining)`. Generator timeout in `thread` mode (abandons the thread, loop never calls it again) or `process` mode (forked child, whole process group SIGKILLed). Separate `baseline_timeout_seconds` / `candidate_timeout_seconds`. A candidate cut short by the global deadline is flagged `budget_cut` and is **not** written to the failure ledger (it did not fail; we stopped it). Measured: overrun 0.00 s (generator) and 0.01 s (hanging candidate) on 4 s / 5 s budgets.
2. **Reliable baseline.** Baseline runs `baseline_runs` times (default 2) in fresh copies; flaky failing sets -> `baseline_unstable` (flaky tests listed); timeout -> `baseline_timeout`; zero tests -> `no_tests_collected`; usage/internal/crash -> `baseline_error`; collection errors stay repairable. Passing candidates are re-run `confirm_runs` times (default 1); a pass that does not reproduce is `unconfirmed_pass` and never accepted.
3. **Comparison / regression detection.** Exact per-test outcomes via JUnit XML (passed/failed/error/skipped/xfailed). Per attempt: fixed, regressions (including new failing ids), **vanished tests**, **newly skipped tests**. A "passing" run that lost or skipped tests is `rejected_test_loss` (this also catches whole-module skip, exit code 5). Ranking is `(not accepted, vanished, regressions, new skips, failing, diff size, duration)`; `compare_attempts()` names the deciding criterion; result carries a leaderboard.
4. **Failure memory.** Duplicate detection by **AST-normalized hash** (formatting/comment-only variants are duplicates; a formatting-only change to the current file is rejected). Ledger records now carry repo fingerprint, base hash, normalized hash, error signature, fixed/regressed tests; failures recorded against a **different repo state are marked stale and never block**. Each round's `ctx.feedback` has: what was tried, tests still failing, partial progress per test, regression culprits, repeated failure modes (counted by signature), rejection counts, protected paths, budget left. Ledger: locked + fsynced appends, torn final line tolerated and truncated, tampering/mid-file corruption still raises, legacy DEV8 records still read.
5. **Safer candidate/test handling.** Test run: process-group kill (grandchildren too, plus stray-process cleanup after passing runs), scrubbed environment (no inherited secrets, throwaway HOME/TMPDIR, fixed hash seed), rlimits (CPU, address space, file size, no core), network namespace isolation when `unshare` works (loopback kept up), symlink-free repo copies. Candidate screening: protected tests **and config/build files** (pytest.ini, pyproject.toml, setup.cfg, tox.ini, setup.py, conftest.py, .coveragerc), allowed suffixes (default `.py`), size cap, and a static scan that rejects **newly introduced** network/process/native/destructive-FS/dynamic-exec constructs (pre-existing ones don't block; `allow_risky` / `block_risk_categories` override).

## Bugs found by my own tests during this work (all fixed, all covered)
Torn-tail "healing" that would have made the ledger permanently unreadable; CPU limit with soft==hard sending SIGKILL so the cause was misreported; a module that skips itself away (exit code 5) not treated as total test loss; plain `assert` failures yielding no exception name in failure signatures. One original DEV8 test was changed: it padded a candidate with comments, which is now (correctly) rejected as formatting-only; padding is now real code.

## Validation actually run
- 49 new tests (46 + 3 added after mutation review); `test_alpha8_*`: **249 passed**, 8 subtests; the 14 original DEV8 tests all pass; `compileall` clean.
- Historical groups identical to pristine DEV7: v01 72 passed; v02 13 failed; v03 3 collection errors; v04 6 failed (PyTorch absent in this environment).
- **Mutation check:** 16 deliberate defects across the new behaviors; the first pass caught 15, the survivor exposed a coverage gap (ledger masking the in-session duplicate path), a test was added, and all 16 are now caught.
- Cost (trivial repo, measured): SafeTestRunner 0.27 s/run vs 0.22 s legacy; default settings (2 baseline + candidate + 1 confirm) 1.09 s vs 0.54 s minimal (`baseline_runs=1, confirm_runs=0`). Larger suites scale this ~2x; tune if too slow.

## Limits — read before relying on this
- **Not an OS security boundary.** No filesystem namespace or seccomp: a hostile test can still read world-readable files and write anywhere the user can. Network isolation depends on `unshare`/user namespaces and is reported as `NOT isolated` when unavailable. Use a container/VM for untrusted code.
- The risk scan is heuristic; obfuscated code evades it. It is a speed bump plus an audit signal, not protection.
- `thread` generator timeouts cannot kill the thread. `process` mode kills it but uses `fork` (POSIX only; falls back to thread with a note elsewhere; Python warns about forking from multi-threaded parents) and the generator **loses in-memory state between rounds**.
- Flaky detection with 2 runs misses low-probability flakiness; fixed `PYTHONHASHSEED=0` reduces hash-order flakiness but can also mask it. `RLIMIT_AS` (default 4096 MB) can break memory-hungry libraries: set `memory_mb=None` to disable.
- Symlinks are not copied, so a baseline that depends on them can fail for that reason (reported in `baseline.skipped_symlinks`).
- Single-file candidates, Python/pytest only. No code-generating model exists in ASM; no benchmark was run, so **no improvement in coding ability is claimed** — this release is about reliability and safety of the evaluation loop.

## Promotion gate for DEV8.1
(1) Real generator adapter; (2) measured false-accept rate (passes tests but fails held-out tests) with vs without confirmation and vanished-test checks, on foreign repos; (3) fault-injection pass on the sandbox inside a real container to quantify what rlimits/netns actually stop; (4) larger-suite timing; (5) human sign-off before any apply to a real tree.
